## FINDINGS

### MUST-FIX (all fixed in-run)

**R-1 [CQ-2 / STRUCT-2] A reserve that looks configured gates nothing**
File: `src/claude_swap/settings.py:337`
Confidence: 95 (reproduced empirically by two independent auditors)
Evidence: `_clamped()`'s bare-int→string coercion was hardcoded to `"homeAccount"`.
`reserveAccount`'s own help says "num or email", but `{"autoswitch": {"reserveAccount": 3}}`
fell through to `spec.default` (None). The "string" kind has no warning path (unlike
"choice"), so the reserve read as unset with no signal — the inert-pin failure the
`homeAccount` comment one line above already warns about, repeated one key later.
Fix: generalised to `_SLOT_IDENTIFIER_KEYS = ("homeAccount", "reserveAccount")` so the
next "num or email" key inherits it. Tests: `TestReserveSettingsClamp` (2).

**R-2 [CQ-1] A forced escape bypassed the margin `_return_home` enforces**
File: `src/claude_swap/autoswitch.py:2650-2666` vs `:3269-3276`
Confidence: 90 (reproduced empirically against the frozen checkout)
Evidence: the prefer-mode ranking key was `(unhealthy,)` — bare account-sequence order,
headroom magnitude ignored. `_return_home` refuses to land on home unless
`available >= (100 - threshold) + hysteresis_pct`; an at-limit/failover escape reaches
the generic ranking path instead and never applied that margin. Reproduced: home at 5%
life, another account at 90% → the engine took home, then would escape again next tick.
That is precisely the flapping `test_small_quota_jitter_does_not_cause_return_flapping`
pins for the return path, defeated by the one path that did not check.
Fix: demote a home below the margin behind the healthy field
(`key = (unhealthy, home_refused)`); sequence order still orders the rest.
Tests: `TestPreferredEscapeHonoursTheReturnMargin` (2) — closes the Q7/Q11 gap the CQ
auditor scored on `test_preferred_home.py`.

**R-3 [ADV #5,#6,#7] The type-check gate could pass without running mypy**
File: `verification/typecheck.py:18-36`
Confidence: 100 (reproduced — the gate now raises where it previously printed 0)
Evidence: `python -m mypy` exits 1 both for "found errors" and for "No module named
mypy". `check()` accepted exit 1, read empty stdout, returned an empty Counter — so
baseline and current were both 0 and the gate printed `introduced=0` having type-checked
nothing. `mypy` is NOT in `verification/requirements.txt` (verified), so a fresh farm
environment hits exactly that path.
Fix: demand the summary line mypy always emits (`Success:` / `Found N error`), else
raise naming the stderr and the install command.

**R-4 [ADV #8] The fallback baseline compared the commit against itself**
File: `verification/typecheck.py:38-52`
Confidence: 85
Evidence: with `verification/upstream-src.tar` absent, the fallback archives `HEAD` —
the commit under test — so baseline and current are the same source and `introduced` is
0 by construction. A vacuous pass, and a silent one.
Fix: kept the fallback (removing it would break a working path) but made it print a
WARNING stating that `introduced=0` proves nothing and the pinned baseline must be
restored.
