**ATTACK VECTOR:** `live_email()` swallows `OSError`/`ValueError` and returns `None` — that covers a half-written `sequence.json`, a locked file, NFS blip, or a bad backup root. `once()` then sends `"{}"` and the REMOTE block `os.replace`s it over ryzen's `peer-active.json`. The same fail-open ordering applies when the remote half dies: REMOTE writes the Mac's record (lines 31-34) *before* reading `sequence.json` (line 35), so a traceback there means ryzen's copy of the Mac's state landed while the Mac's copy of ryzen's never did — asymmetric protection with no error surfaced.
**SUGGESTED FIX:** Have `live_email()` distinguish "unreadable" from "no account" (raise / return a sentinel) and skip the push half entirely when unreadable; only push `"{}"` for a verified empty state.
