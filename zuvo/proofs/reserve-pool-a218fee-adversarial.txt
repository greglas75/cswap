FILE: src/claude_swap/autoswitch.py:2140
ID: autoswitch.py:2140:live-pooled-reserve-unread-week-flap
ISSUE: Whether a reserve is pooled now depends on a per-tick, fallible usage read, so a live reserve is treated as a held reserve whenever that read fails.
ATTACK VECTOR: In pool mode the owner sits on a reserve with 60% of its week left. One tick's usage fetch returns a `str` sentinel or `None` (429, network blip, token refresh). `weekly_life` returns `None`, so `_reserve_slots` keeps the account in the reserve set. `on_reserve` becomes True and the "never a resting place" handover fires, moving the owner off a healthy account. The next good read pools it again, it can win the ranking, and the engine lands on it again. Each hop swaps credentials under running sessions. The docstring only argues that an unread week must not put the account into rotation; it ignores that the same rule ejects the live account. `cswap list` reads `entry.last_good` while the engine reads the tick's `usage`, so the list can show "in rotation" while the engine treats the account as held.
SUGGESTED FIX: For the live account (`current`), treat unknown life as "keeps its current class". For example, in the pool filter skip any slot where `life is None` and `num == current`, or fall back to the last known good weekly life.

SEVERITY: WARNING
CONFIDENCE: medium
FILE: src/claude_swap/autoswitch.py:3567
ID: autoswitch.py:3567:pool-floor-no-margin-overshoot
ISSUE: A reserve is pooled at `life >= floor` with no margin or look-ahead, so a reserve at floor+ε can be chosen and then burn past the floor before the next tick.
ATTACK VECTOR: The reserve has 21% of its week left (floor 20). It is now an ordinary account, and with a fresh 5h window it usually has the most headroom, so it ranks first. One 5h session consumes far more than the 1% above the floor, and the weekly floor is only re-checked on later ticks. In "last" mode this overshoot was rare because the reserve was a last resort. In "pool" mode it is the common case, which defeats the owner's "use it up to 80%" intent.
SUGGESTED FIX: Pool only when `life >= floor + margin`, or apply the existing pace/climb look-ahead to the weekly floor for pooled reserves. Use hysteresis: enter above floor+margin, and leave when the floor is crossed.
