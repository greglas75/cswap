FILE: src/claude_swap/agy.py:210
ID: agy.py:210:stored-accounts-unvalidated-json
ISSUE: `stored_accounts()` now derives account identity from the *contents* of every `*.json` in the store via `email_of(read_file(p))` with no error handling and no cheap pre-filter. The previous `p.name != QUOTA_STATE` guard was dropped, so `quota.json` (and any file) is parsed too.
ATTACK VECTOR: The comment itself concedes other tools drop their own JSON into this directory ("2026-10-16: `*.token.json`, probe-state.json"). `read_file` almost certainly does `json.loads(path.read_text())`, so a single malformed file (a partially-written foreign file, a truncated cswap backup from a crashed `write_private`, or a directory accidentally named `*.json` → `IsADirectoryError`) raises out of the comprehension and breaks the entire account listing. Even for well-formed foreign files, if `email_of` doesn't return a value exactly equal to the filename stem, the entry is *silently* omitted — a corrupt or legacy account file vanishes with no warning. Listing now also reads/parses every JSON in the store on each call (was previously content-blind).
SUGGESTED FIX: Wrap the predicate so a bad file cannot abort the listing, e.g. a helper `def _is_login(p): try: return email_of(read_file(p)) == p.name[:-len(".json")] except (OSError, ValueError): return False`, and re-add `p.name != QUOTA_STATE`.

FILE: src/claude_swap/agy.py:67
ID: agy.py:67:live-files-exists-stat-toctou
ISSUE: `live_files()` tests `p.exists()` in the comprehension and then `p.stat().st_mtime` in the sort key — a check-then-use race on the real filesystem.
ATTACK VECTOR: `agy` rewrites/rotates its login file concurrently (unlink+recreate). If the file is removed between `exists()` (returns True) and `stat()`, `stat()` raises `FileNotFoundError`, which propagates out of every caller (`live_file()`, `write_live()`, `clear_live()`). On POSIX, a rename-based writer is usually safe, but a delete/shorter window (e.g. keychain sync, another cswap instance) makes this flaky.
SUGGESTED FIX: Compute mtime defensively, e.g. `found = [p for p in ... if p.is_file()]` and sort with a key that tolerates a vanished file: `key=lambda p: p.stat().st_mtime if p.exists() else 0.0`, or `try/except FileNotFoundError` per path.

ISSUE: `count()` returns `None` for any non-`int`/`float` value and calls `int(v)` on any float, without validating finiteness. (`float` also truncates fractional counts.)
ATTACK VECTOR: (a) If the API serializes a valid count as a numeric *string* (common in JSON APIs), the value is silently discarded and the `limit resets` line never appears — a silent feature regression the test even hard-codes by treating `"x"` as garbage. ID: agy.py:75:restore-writes-wrong-file-after-clear
ISSUE: When no token file exists, `live_file()` guesses the path from the platform only. On non-darwin it always picks the 1.4 file (`antigravity-cli/...`), even if the machine was running an older agy that reads `jetski-standalone-oauth-token`.
ATTACK VECTOR: On Linux with agy ≤1.3, `login()` calls `clear_live()`, which now unlinks both files. If the user cancels or the sign-in fails, `write_live(previous)` runs with `live_files()` empty and writes only `antigravity-cli/antigravity-oauth-token`. The old agy reads the jetski file, so the machine stays logged out even though `login()` says "the previous one is back in place". The same applies to `_switch` when the live login is already gone: it writes only the 1.4 path.
SUGGESTED FIX: Remember which files existed before `clear_live()` and restore to those. Or, when nothing exists, write both paths.

SEVERITY: WARNING
CONFIDENCE: medium
FILE: src/claude_swap/agy.py:64
ID: agy.py:64:mtime-decides-live-login
ISSUE: "Newest mtime is live" is the only signal for which file is the current login, and `exists()` then `stat()` is not atomic.
ATTACK VECTOR: Any `cp`, rsync or restore without `-p`, or a `touch`, makes the stale file the newest. `read_live()` then returns the wrong account, and `_sync_live` can write that stale token into the stored file of the account it names. A partial failure in the `write_live` loop leaves one file with the old account. `stat()` also raises `FileNotFoundError` if a file disappears between `exists()` and `stat()`. That would crash `auto_tick` and `read_live` instead of treating the file as absent.
SUGGESTED FIX: Wrap `stat()` in `try/except OSError`, skipping the file. Prefer a file whose email matches the stored or last-synced account on a tie or a suspiciously old mtime.
