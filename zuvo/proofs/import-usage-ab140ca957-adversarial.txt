**SEVERITY: WARNING**
**CONFIDENCE: high**
**FILE:** src/claude_swap/transfer.py:~654 (import_usage validation) / src/claude_swap/usage_store.py:~880 (`adopt` hold stamping)

**ISSUE:** Freshness is measured at document *production* time only; nothing bounds the production→import gap, so a stale document imports as fresh — indefinitely.

**ATTACK VECTOR:** `usageAgeSeconds` is captured when the producer ran `list --json`. `import_usage` reads only `schemaVersion` and per-row fields — no document-level timestamp is consulted, so `fetchedAt` is reconstructed as `import_time − age`. The tool's stated use case is *scripted* hand-off ("a script can let one machine poll and hand its readings to the rest"). If the producer dies (Mac asleep, uninstalled, path moved) while a consumer keeps importing the same shared file on a schedule, every import re-stamps `fetchedAt ≈ now`, beats any locally newer reading, re-arms `heldUntil` (capped at `TRUST_MAX_AGE_S` from the *re-stamped* time), and `entries()`/`due_candidate`/`_row_eligible` then actively suppress re-polling while serving the frozen reading as decision-trusted. The consumer never falls back to self-polling and never errors — week-old usage presented as current, forever.

**SUGGESTED FIX:** Have `list --json` emit a top-level `generatedAt` (epoch); in `import_usage`, compute effective age as `usageAgeSeconds + max(0, now − generatedAt)` and reject (or refuse to hold/adopt) documents older than `TRUST_MAX_AGE_S`.

**FILE:** src/claude_swap/usage_store.py:~864 (`adopt`: `if not readings: return set()`) with src/claude_swap/transfer.py:~679 (non-ok rows skipped before slot matching)

**ISSUE:** `--hold 0` ("lifts an earlier hold" per CLI help) is a silent no-op exactly when lifting is needed.
