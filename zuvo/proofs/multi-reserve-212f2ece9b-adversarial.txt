**FINDING 1**

SEVERITY: WARNING
CONFIDENCE: high
FILE: src/claude_swap/settings.py (parse_reserves, the `else: ident = part` branch)
ISSUE: A non-numeric suffix (the most likely typo class — `"greg:40%"`, `"greg:abc"`, trailing `"greg:"`) causes the *entire entry, suffix included*, to be treated as the identifier, which then resolves to no managed account and is silently skipped — the account is un-reserved with zero warning logged.
ATTACK VECTOR: Operator writes `reserveAccount: "greg@x.com:40%"` (percent sign is the natural typo for a "pct" field). `float("40%")` raises ValueError → `ident = "greg@x.com:40%"` → `_resolve_reserve` / `slot_of` find nothing → entry dropped. The reserve protection the operator explicitly configured is gone, silently, and the fleet can now burn the account that "has to stay." Note the asymmetry: the out-of-range-numeric path (`"greg:150"`) logs a warning *and* still reserves the account; the non-numeric path does neither.
COMMENT-CODE MISMATCH: The docstring states "the entry falls back to the default floor rather than being dropped: **a typo must never un-reserve the account**." The `else: ident = part` branch does exactly what the docstring promises never happens — this typo class un-reserves the account.
SUGGESTED FIX: In the `parsed is None` branch, log a warning mirroring the out-of-range branch and use `ident` (the rpartition prefix) with `default_floor` instead of reassigning `ident = part` — or, if keeping the suffix-as-identifier behavior for exotic names, at minimum warn when the entry later fails to resolve in `_reserve_slots`/`slot_of`.
